# ADR-013: Sandbox Policy for Agent-Generated Code

- **Status**: Proposed
- **Date**: 2026-04-29
- **Deciders**: agentguard-architecture-swarm
- **Bounded Context**: Security, CodingAgent

## Context

Coding-agent tests will frequently execute code generated by the agent (e.g., to compute First-Run Test Pass Rate, ADR-010). Skill graders may execute scripts referenced by `SKILL.md`. Without sandboxing, a malicious skill (ToxicSkills/ClawHavoc, ADR-006) or a hallucinated `rm -rf /` from a coding agent will execute on the runner's host (research risk #2).

UK AISI's Inspect AI ships a sandbox toolkit covering Docker, Kubernetes pods (one per sample), and Proxmox. This is the de-facto OSS standard for safety-grade evaluation and is used by METR and Apollo Research (research §2.2). Reusing it avoids reinventing isolation primitives.

Default-deny is the right policy: code execution must be **opt-in** via an explicit flag, not opt-out. CLAUDE.md security rules require this stance.

## Decision

Integrate **Inspect AI's sandbox toolkit** (Docker / K8s pods-per-sample / Proxmox) for any keyword that runs agent-generated code or skill scripts. Require an explicit **`--allow-code-execution`** flag (also expressible as `Library AgentGuard allow_code_execution=${TRUE}`). Without the flag, any code-execution keyword raises `CodeExecutionDeniedError` and prints remediation guidance.

## Rationale

- Inspect AI sandbox toolkit is the established AISI/METR/Apollo standard (research §2.2).
- Docker is universally available; K8s pod-per-sample scales for parallel CI; Proxmox covers VM-level isolation when needed.
- Explicit opt-in flag matches CLAUDE.md security rules and prevents silent escalation.
- Pairs with ADR-006 (default-deny skills) to give defence-in-depth: even an allowlisted skill can only execute inside the sandbox.

## Consequences

- **Positive**: Safe to test untrusted skills and run coding agents in CI; one sandbox abstraction across multiple isolation backends; auditable consent.
- **Negative**: Docker/K8s adds CI infrastructure requirements; Inspect AI dependency adds package weight (mitigated by `agentguard[sandbox]` extra).
- **Neutral**: Per-sample pod isolation has measurable per-test overhead; teams can opt to reuse one sandbox across tests at slightly elevated risk.

## Alternatives Considered

- **Option A — Roll our own subprocess sandbox**: rejected, isolation is hard to get right; Inspect AI already solved it.
- **Option B — Ban code execution entirely**: rejected, prevents First-Run Test Pass Rate (a #42796 metric, ADR-010) and skill-grading workflows.
- **Option C — Default-allow with deny list**: rejected, contradicts CLAUDE.md security stance and OWASP boundary-validation guidance.
